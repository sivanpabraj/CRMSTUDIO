# راهنمای عملیات و بازیابی

## مانیتورینگ

Workflow روزانه `Operations integrity` توازن دفترکل، نبود head یتیم و endpoint سلامت نسخه مستقر را کنترل می‌کند. دو secret مخزن باید تنظیم شوند:

- `SUPABASE_DB_URL`: اتصال فقط برای اجرای کنترل‌های عملیاتی
- `DEPLOYMENT_HEALTH_URL`: آدرس Edge Function سلامت

خطای این Workflow باید هشدار عملیاتی ایجاد کند و تا رفع علت، انتشار متوقف بماند.

## بکاپ

بکاپ مرورگر فقط برای بازیابی دستگاه کاربر است و جای بکاپ سرور را نمی‌گیرد. checksum هر خروجی محلی ثبت می‌شود تا خرابی فایل تشخیص داده شود.

برای دیتابیس production باید Supabase PITR/backup روزانه فعال شود:

1. نگهداری حداقل ۳۰ روز
2. یک restore آزمایشی ماهانه روی پروژه جداگانه
3. ثبت زمان بازیابی و نتیجه کنترل `scripts/ops-integrity.sql`
4. ممنوعیت ذخیره dump دارای اطلاعات مشتری در GitHub Artifacts

## رخداد مالی

در صورت شکست کنترل توازن:

1. عملیات مالی جدید متوقف شود.
2. آخرین command و journal مرتبط از روی idempotency key مشخص شود.
3. داده به‌صورت دستی حذف یا ویرایش نشود.
4. اصلاح فقط با command برگشتی ثبت شود.
5. پس از توازن، گزارش رخداد و علت ریشه‌ای ثبت شود.

## انتشار

ابتدا migration روی staging، سپس تست RLS و مالی، بعد artifact نسخه ساخته می‌شود. استقرار production بدون restore point و تأیید checkهای CI مجاز نیست.
