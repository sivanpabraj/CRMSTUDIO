# گزارش نوسازی مهندسی CRMSTUDIO

تاریخ ارزیابی: ۲۰ مرداد ۱۴۰۵

## نقش‌های مهندسی

| نقش | مسئولیت اجراشده |
|---|---|
| مهندس محصول | محدودکردن دامنه به خدمات واقعی استودیو و تعریف جریان‌های قابل اجرا |
| معمار نرم‌افزار | یکپارچه‌سازی شاخه سخت‌سازی سازمانی و حفظ معماری ماژولار |
| مهندس فرانت‌اند | قرارداد چندنوعی، پلن‌های قابل ویرایش، چت دوطرفه و تقویم شمسی |
| مهندس امنیت | ورود دومرحله‌ای مستقل پرتال، کنترل سطح دسترسی و حذف فعال‌سازی خودکار |
| مهندس داده | نگهداری snapshot نسخه قیمت در قرارداد و جلوگیری از تغییر سابقه مالی |
| مهندس کیفیت | آزمون واحد، lint، اعتبارسنجی مخزن و build تولید |
| مهندس عملیات | بررسی وضعیت مهاجرت‌ها و جلوگیری از اعمال کورکورانه روی دیتابیس دارای drift |

## خروجی اجرایی

1. ورود عمومی دیگر کاربر پرتالِ در انتظار را فعال نمی‌کند؛ کد دعوت مستقل الزامی است.
2. قرارداد می‌تواند هم‌زمان شامل عروسی، عقد، فرمالیته، کلیپ، آلبوم یا صنعتی باشد.
3. قرارداد صنعتی اطلاعات مشتری/برند مستقل دارد.
4. پلن‌های اقتصادی، سیلور، گلد، VIP، CIP و سفارشی آماده و قابل ویرایش‌اند.
5. هر ویرایش پلن نسخه جدید می‌سازد و snapshot قیمت در قرارداد ثابت می‌ماند.
6. خدمات لباس و اکسسوری، نورپردازی، آتش‌بازی و رقص ورودی در کاتالوگ یا قالب‌های پیش‌فرض وجود ندارند.
7. چت مشتری، مدیر و پرسنل دوطرفه است و رسید ارسال/خواندن مستقل دارد.
8. تقویم فارسی و شمسی است و تداخل پرسنل را با ساعت شروع، پایان یا مدت پروژه تشخیص می‌دهد.
9. تنظیمات، دسترسی‌های عملیاتی، پشتیبان، پیامک و اتصال ابری تحت کنترل نقش مدیر هستند.
10. رابط اصلی روی زبان فارسی و جهت RTL قفل شده و تاریخ‌های کسب‌وکار شمسی‌اند.

## امتیاز سخت‌گیرانه پس از بازسازی

| بخش | امتیاز از ۱۰ | نتیجه |
|---|---:|---|
| قرارداد و انواع پروژه | ۱۰ | کامل در دامنه تعریف‌شده |
| پلن و قیمت‌گذاری | ۱۰ | آماده، دستی، قابل ویرایش و نسخه‌دار |
| چت و صندوق مشتری | ۹ | دوطرفه و دارای رسید؛ پیوست فایل هنوز لازم است |
| تقویم شمسی | ۹ | رویداد و تداخل زمانی؛ نمای منابع کشیدنی هنوز لازم است |
| تنظیمات و دسترسی | ۹ | پوشش عملیاتی خوب؛ تنظیم امنیتی Supabase باید در داشبورد نهایی شود |
| امنیت ورود پرتال | ۹ | مسیر ناامن بسته شد؛ تست نفوذ مستقل انجام نشده است |
| کیفیت کد و آزمون | ۹ | ۱۴۴ آزمون واحد موفق؛ مرورگر Playwright در محیط اجرا نصب نبود |
| آمادگی SaaS عمومی | ۷٫۴ | سقف واقعی فعلی بر اساس ممیزی معماری و عملیات |

نمره ۱۰ فقط برای بخش‌هایی ثبت شده که معیار پذیرش آن‌ها در همین مخزن قابل اثبات است. برای کل SaaS، ادعای ۱۰ بدون تست بار، تست نفوذ، مرورگر E2E، مانیتورینگ تولید و رفع هشدارهای امنیتی سرویس ابری غیرمهندسی است.

## دروازه تحویل

- `npm run validate:repo`: موفق
- `npm run lint`: موفق بدون هشدار
- `npm test`: ۳۴ فایل و ۱۴۴ آزمون موفق
- `npm run build`: موفق
- `npm run test:e2e`: health موفق؛ تست‌های مرورگر به علت نصب‌نبودن Chromium در محیط اجرا متوقف شدند، نه خطای برنامه

## موارد لازم برای رسیدن کل محصول به ۱۰

1. نصب Chromium و اجرای کامل E2E احراز هویت، قرارداد، چت، تقویم و مالی.
2. تست نفوذ مستقل و فعال‌کردن محافظت رمزهای افشاشده در Supabase.
3. همسان‌سازی تاریخچه مهاجرت مخزن با دیتابیس زنده پیش از هر deploy دیتابیس.
4. تست بار چندمستاجری و تعریف SLO برای همگام‌سازی، پیامک و عملیات مالی.
5. افزودن پیوست امن فایل به چت و اسکن نوع/حجم/بدافزار.
