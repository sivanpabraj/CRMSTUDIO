# تصمیم معماری: عملیات مالی آفلاین قطعی نیست

## تصمیم

ثبت مالی بدون تأیید سرور مجاز نیست. در حالت آفلاین یا نبود نشست معتبر، برنامه پیام خطا نشان می‌دهد و هیچ موجودی، پرداخت قرارداد یا تراکنش قطعی را در IndexedDB تغییر نمی‌دهد.

## دلیل

صفی که ابتدا پول را محلی ثبت کند و بعداً از سرور اجازه بگیرد، منبع حقیقت واحد ایجاد نمی‌کند و ممکن است پس از رد سرور یا تعارض نسخه، بدهی و موجودی اشتباه نمایش دهد.

## وضعیت FinanceOutbox

کد قدیمی Outbox برای سازگاری داده‌های قبلی نگه داشته شده، اما مسیرهای جدید مالی آن را برای ثبت قطعی استفاده نمی‌کنند. پس از تسویه همه رکوردهای قدیمی، این ماژول باید در migration پاکسازی جداگانه حذف شود.
